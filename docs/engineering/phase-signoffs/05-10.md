## Confirmed defects fixed during review

- Tailwind preflight required explicit inline-link underlines; axe found and verified the fix.
- A root loading Suspense boundary caused HTTP 200 streamed missing-venue responses. Loading now belongs to discovery only; production detail/report missing-ID tests return 404.
- A pre-hydration report could submit through native GET and put fields in a URL. Submit is disabled until hydration; native fallback is explicitly POST; no-JavaScript messaging is provided.
- Canonicalized report ID/time and dimension order before hashing, preventing equivalent offset/key-order variants of a duplicate payload.
- Reject all-null/malformed/future/foreign-parent/duplicate-ID observations in shared scoring. Missing intensity is never zero.
- Required facilities use fresh verified true only, preserving false/unknown/stale distinctions.
- Source URL scheme/credentials, time zones, coordinates, venue visibility and raw report payloads are validated before public serialization.
- Public query failures and capacity truncation are explicit errors; no silent local fallback or fabricated zero-report success for failed requests.
- Scoped IPv6 ingress values are rejected safely; Node accepts zone identifiers as IPs, but URL normalization does not. A malformed trusted header cannot trigger that exception.

Some intermediate browser failures were fixture/assertion defects: future test source timestamps, assertions racing navigation, unnamed alerts colliding with Next's route announcer, and hidden streamed duplicate text. The final suite uses source timestamps before request time, named alerts, route-completion assertions and accessible heading queries. No production result was inferred from a failed run.
